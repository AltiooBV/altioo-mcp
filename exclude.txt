# What is kept out of the release archive.
#
# README.md and doc/ are deliberately NOT listed: the archive is what an
# administrator finds on the instance in a year's time, and documentation that
# only exists on a web page is documentation that instance does not have.
# tests/ ships too - iTop's own Extensions testsuite scans env-production/.
# tools/ does not: it is maintenance tooling for this repository, and it reads
# git history, which no installed copy has.
#
# AGENTS.md and doc/itop-branch-notes.md are the exception to the rule above,
# and not for size: they are CC BY-SA 4.0, while LICENSE, composer.json,
# extension.xml and the README all declare the package AGPL-3.0-or-later with
# no NOTICE beside it. Two differently-licensed files landing on a customer
# instance is a provenance claim the package cannot support. They also describe
# how this repository is worked on, which is not something an installed copy
# has any use for. phpcs.xml.dist goes with them: it points at tools/, which
# is not in the archive. This file excludes itself for the same reason: it
# describes how the archive was built, which is a question about the build and
# not about the instance.
#
# doc/example-pack ships as source and only as source. Its vendor/ and its lock
# are what appear when somebody follows its README and runs composer in there -
# a whole test framework, landing inside doc/ on a customer instance. .gitignore
# already keeps both out of the repository, so a release CI builds from a clean
# checkout never saw them; one built from a working tree that had followed the
# pack's own instructions would ship them. Two filters, and this is the case
# where only one of them was looking.
